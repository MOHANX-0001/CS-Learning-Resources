CH 01

Process Deadlocks

📖 Definition

What is a Deadlock?

A deadlock is a situation where a set of processes are blocked indefinitely, each holding a resource and waiting for another resource that is held by another waiting process — forming a circular chain.

Example: P1 holds Printer, needs Disk. P2 holds Disk, needs Printer. Neither can proceed → Deadlock!
📝 Short Note

4 Necessary Conditions for Deadlock (Coffman, 1971)

All four must hold simultaneously:

#ConditionMeaning
1Mutual ExclusionOnly one process can use a resource at a time (non-shareable).
2Hold & WaitA process holds ≥1 resource AND is waiting for more resources held by others.
3No PreemptionA resource cannot be forcefully taken away; only voluntarily released.
4Circular WaitP0→R1→P1→R2→P2→...→Pn→R0→P0 — a circular chain of waiting processes.
📊 Diagram

Resource Allocation Graph (RAG)

A directed graph to detect deadlock. Two types of edges:

  • Request Edge Pi → Rj: Process Pi is requesting resource Rj (not yet allocated)
  • Assignment Edge Rj → Pi: Resource Rj is allocated to process Pi
RAG — With Deadlock (Cycle = Deadlock if single instances)
  ┌────┐  Request   ┌════╗   Assigned  ┌────┐
  │ P1 │───────────▶║ R1 ║────────────▶│ P2 │
  └────┘            ╚════╝            └────┘
     ▲                                    │
     │  Assigned  ┌════╗   Request        │
     └────────────║ R2 ║◀─────────────────┘
                  ╚════╝

  Cycle: P1→R1→P2→R2→P1  ⟹  DEADLOCK ✗
Rule: If graph has no cycle → No deadlock. If cycle exists + single instance per resource → Deadlock. If cycle + multiple instances → May or may not be deadlock.

⚙️ Core Working

Deadlock Prevention — How it Works

Eliminate one of the 4 conditions:

  • Mutual Exclusion: Make resources shareable (hard for printers)
  • Hold & Wait: Process must request ALL resources at once before starting
  • No Preemption: If a process requests and fails, preempt its resources
  • Circular Wait: Assign priority numbers; request resources only in increasing order
📖 Definition

Safe State & Deadlock Avoidance

A state is safe if the system can allocate resources to every process in some order and avoid deadlock.

  ┌───────────────────────┐
  │         Unsafe         │
  │  ┌─────────────────┐  │
  │  │   Deadlock      │  │
  │  └─────────────────┘  │
  └───────────────────────┘
  ┌───────────────────────┐
  │   Safe  (No Deadlock) │
  └───────────────────────┘

Safe sequence <P1,P2,...Pn>: Each Pi's remaining needs ≤ currently available + resources held by all Pj (j<i)

⚙️ Core Working

Banker's Algorithm (Dijkstra, 1965) — Multiple Instances

Named after banking: bank never allocates cash so it can't satisfy all customers. Data structures needed:

StructureSizeMeaning
Available1×mAvailable instances of each resource type
Maxn×mMax demand of each process
Allocationn×mCurrently allocated to each process
Needn×mRemaining need = Max − Allocation
① Safety Algorithm
  1. Work = Available; Finish[i] = false for all i
  2. Find i where Finish[i]=false AND Need[i] ≤ Work
  3. Work = Work + Allocation[i]; Finish[i] = true → go to step 2
  4. If Finish[i]=true for all i → SAFE STATE ✓
② Resource-Request Algorithm
  1. If Request[i] > Need[i] → Error (exceeded max)
  2. If Request[i] > Available → Wait
  3. Pretend to allocate: Available−=Request; Allocation+=Request; Need−=Request
  4. Run Safety Algorithm → if Safe: Allocate; if Unsafe: Rollback & Wait
⚙️ Core Working

RAG Algorithm — Single Instance

Uses a special claim edge (dashed line): Pi may request Rj in future.

  • Claim edge → Request edge when process actually requests
  • Request edge → Assignment edge when resource is granted
  • Rule: Grant only if conversion does NOT create a cycle
  • Cycle in graph → Unsafe state → Deny request
⚙️ Core Working

Deadlock Detection

Single instance: Use Wait-For Graph — remove resources, keep only process nodes. If cycle exists → Deadlock.

Multiple instances: Algorithm similar to Banker's (uses Available, Allocation, Request matrices). If Finish[i]=false after algorithm → Pi is deadlocked.

Complexity: O(m × n²) operations
📝 Short Note

Recovery from Deadlock

Method 1 — Process Termination:

  • Kill ALL deadlocked processes (expensive but guaranteed)
  • Kill ONE at a time until deadlock is broken (run detection after each kill)

Method 2 — Resource Preemption:

  • Select Victim: based on priority, cost, completion %
  • Rollback: roll process back to safe state
  • Starvation: ensure same process not selected repeatedly

CH 02

File System Management

📖 Definition

What is a File?

A file is a named collection of related information stored on secondary storage. It is the logical storage unit of the OS.

A File System is the part of the OS responsible for organizing, managing, and retrieving files. It resides on disk permanently.

📝 Short Note

File Attributes

  • Name — Symbolic file name
  • Identifier — Unique tag/number in file system
  • Type — Type of file
  • Location — Pointer to device/location
  • Size — Current size in bytes/blocks
  • Protection — R/W/X access control
  • Time/Date/User — Created, modified, last accessed

📝 Short Note

File Access Methods

1. Sequential Access — Read/write in order from beginning. Like tape model. Simple Slow for search

2. Direct Access (Random) — Read/write block n directly using block number. Fast Disk model

3. Indexed Access — Use separate index file mapping key → address. Two types: Indexed Non-Sequential & Indexed Sequential (ISAM).

CH 03

Disk Scheduling

📖 Definition

What is Disk Scheduling?

Disk scheduling is the technique used by the OS to determine the order in which disk I/O requests are serviced to minimize seek time and maximize throughput.

Key times to know:

  • Seek Time — Time to move disk arm to required track
  • Rotational Latency — Time for disk to rotate desired sector under head
  • Transfer Time — Time to transfer data
  • Access Time = Seek + Rotational Latency

📝 Short Note — All Algorithms

Disk Scheduling Algorithms — Comparison

Example Queue: 95, 180, 34, 119, 11, 123, 62, 64 — Head starts at 50, tail at 199

AlgorithmHow it worksTotal MovementAdv.Disadv.
FCFS Service in arrival order: 50→95→180→34→119→11→123→62→64 644 tracks Fair; no starvation Worst seek time; no optimization
SSTF Always serve nearest cylinder first (like SJF for disk) 236 tracks Less avg response time; high throughput Starvation possible; high variance
SCAN (Elevator) Move in one direction, serve all requests, then reverse at end 230 tracks High throughput; low variance Long wait for just-visited locations
C-SCAN Like SCAN but returns to start WITHOUT servicing on return trip 187 tracks More uniform wait time than SCAN Slightly higher total seek
LOOK Like SCAN but only goes to last request in each direction (not end of disk) 208 tracks Better than SCAN; no unnecessary end traversal Non-uniform waiting time
C-LOOK Like C-SCAN but only goes to last request; jumps back to first request 157 tracks ✓ Best balance; no end-of-disk waste Slightly complex

📝 Quick Tip for Exam

Best Algorithm Selection

Performance depends on number and types of requests. SSTF is common with natural appeal. SCAN performs better than FCFS and SSTF overall. C-LOOK or SCAN is the recommended default. Scheduling algorithm should be a separate OS module for easy replacement.

FCFSWorst seek SSTFGood but starvation C-LOOKBest overall ✓
CH 04

Introduction to Distributed Operating Systems

📖 Definition

What is a Distributed System?

A collection of autonomous computers connected via a communication network, cooperating through message passing to appear as a single system to the user.

A Distributed OS is system software over a collection of independent, networked, communicating nodes, presenting a transparent view of multiple computers as one.

📝 Short Note

Key Design Goals

  • Resource Sharing — Share hardware, software, data geographically
  • Openness — Extensible via published interfaces
  • Scalability — Easily expand from small to large number of machines
  • Transparency — Location, replication, failure transparency
  • Fault Tolerance — Failure of few nodes doesn't affect whole system
  • Concurrency — Multiple tasks execute simultaneously on different machines
📝 Advantages

Advantages of Distributed Systems

  • Improved reliability & availability (fault tolerant via replication)
  • Modular expandability (add nodes without replacing existing)
  • Resource sharing across the network
  • Enhanced performance (concurrent execution)
  • Improved efficiency (load distribution)
📝 Disadvantages

Disadvantages of Distributed Systems

  • Security — Both nodes and connections need securing
  • Software — Very few mature distributed OS software available
  • High setup cost — Expensive hardware + maintenance
  • Overloading — Network congestion if all nodes send at once
  • Data loss — Messages may be lost over communication network

⚙️ Core Working

NFS — Network File System

Developed by Sun Microsystems. Allows clients to access files on remote servers as if they were local.

  • Uses RPC (Remote Procedure Calls) for client-server communication
  • Client-server architecture: NFS client ↔ NFS server
  • VFS (Virtual File System) interface routes operations to local FS or NFS client
  • NFS is independent of local file systems (portable)
  • NFSv3 (widely used) and NFSv4 (latest)
📖 Definition

Types of Distributed Systems

  • Cluster Computing: Homogeneous systems (Linux Beowulf clusters) connected via LAN for high performance
  • Grid Computing: Heterogeneous, widely dispersed nodes sharing resources
  • Cloud Computing: On-demand network access to shared pool of configurable resources (SaaS, PaaS, IaaS)
CH 05

Mobile Operating Systems

📖 Definition

What is a Mobile OS?

A Mobile OS (also called mobile platform or handheld OS) is an operating system specifically designed to run on mobile devices like phones, tablets, smartwatches, and PDAs.

It combines PC OS features with mobile-specific features: touchscreen, camera, GPS, Bluetooth, voice recognition, etc.

Examples: iOS, Android, Symbian, BlackBerry OS, Windows Mobile, Palm OS

Special Constraints of Mobile OS

📊 Architectures

Mobile OS Architecture — Key Layers

Underlying OS

Mobile OS is built on top of a base OS kernel (usually Linux for Android, Mach/BSD for iOS). The kernel manages hardware resources.

Kernel Architecture

Microkernel or monolithic. Must be small size for fast booting. Handles process scheduling, memory management, drivers.

Native Level Programming

Low-level C/C++ code that interfaces directly with hardware. Used for performance-critical components.

Power Management

Enters low-power sleep modes quickly. Manages CPU frequency scaling, screen brightness, network radio state.
