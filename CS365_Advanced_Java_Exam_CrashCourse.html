💬 Short Answers for Every Key Topic
What is Collection Framework?

A unified architecture in java.util package with Interfaces (Collection, Set, List, Map), Classes (ArrayList, HashSet, HashMap), and Algorithms (sort, search) to store and manipulate groups of objects.

What is HashSet?

HashSet implements Set interface. Stores unique elements only (no duplicates). Does not maintain insertion order. Backed by a HashMap internally. O(1) for add, remove, contains.

What is TreeSet?

TreeSet implements SortedSet. Stores unique elements in sorted (ascending) order. Implements NavigableSet. Backed by TreeMap. Uses compareTo() for ordering. O(log n) operations.

What is Comparator?

Comparator is a functional interface (java.util) used to define custom sorting. Implements compare(o1, o2) method. Used when natural ordering is not desired or class cannot be modified.

What is Multithreading?

Executing two or more threads simultaneously within a single process. Each thread is an independent path of execution. Makes optimal use of CPU. Java has built-in support via Thread class and Runnable interface.

What is Synchronization?

Controlling access to shared resources by multiple threads. Uses synchronized keyword. A synchronized method/block can be accessed by only ONE thread at a time. Prevents race conditions and data inconsistency.

What is join() method?

t.join() causes current thread to pause until thread t completes execution. Used to ensure a thread finishes before proceeding. Can throw InterruptedException.

What is yield() method?

Thread.yield() temporarily pauses the currently executing thread and gives a chance to other threads of same or higher priority to execute. Does not release any lock. Thread goes back to Runnable state.

What is JDBC?

Java DataBase Connectivity – a Java API to connect Java programs to databases. Uses JDBC drivers to send SQL queries and get results. Part of java.sql package. Write Once Run Everywhere (WORA).

What is commit() and rollback()?

commit(): Makes all changes in current transaction permanent. rollback(): Undoes all changes made since last commit. Used with setAutoCommit(false) for manual transaction control.

What is MetaData?

Data about data. DatabaseMetaData: Info about DB (name, version, tables). ResultSetMetaData: Info about ResultSet (column count, column names, types). Obtained via con.getMetaData() and rs.getMetaData().

What is Servlet?

A Java class that runs on a web server and responds to HTTP requests. Acts as middle layer between HTTP client and backend (DB/applications). Generates dynamic web content. Part of javax.servlet package.

What is JSP?

Java Server Pages – a text document combining static HTML with dynamic Java code. Server processes JSP → converts to Servlet → compiles → executes. Simpler than Servlet for view layer. Uses scripting elements.

What is Session Tracking?

HTTP is stateless. Session tracking maintains client state across requests. 4 methods: (1) Cookies, (2) URL Rewriting, (3) Hidden Form Fields, (4) HttpSession object.

What is a Scriptlet in JSP?

Scriptlet contains Java code that executes per request. Syntax: <% Java code here %>. Placed inside service() method of generated Servlet. Can contain variables, loops, conditionals.

What is Spring Framework?

Open-source Java platform providing infrastructure support for enterprise Java. Created by Rod Johnson, released 2003. Lightweight, IoC-based, supports DI, AOP, MVC, JDBC, transactions. Uses POJO model.

What is IoC in Spring?

Inversion of Control – Spring container controls object creation and dependency management instead of programmer. Objects don't create their own dependencies; the container injects them. Promotes loose coupling.

CH.2 Explain Thread Life Cycle (States of Thread) with Diagram [4–5 M]

Definition

A thread in Java goes through several states from creation to termination. These states together form the Thread Life Cycle.

States of Thread

  1. New: Thread object is created using new keyword but start() not yet called. Thread is in born state.
  2. Runnable: Thread calls start(). Thread is ready to run but waiting for CPU. Scheduler decides when to give CPU.
  3. Running: Thread gets CPU time and executes run() method. Thread scheduler selects it from Runnable pool.
  4. Blocked/Waiting: Thread is alive but not eligible to run. Caused by: sleep(), wait(), join(), or waiting for I/O.
  5. Terminated (Dead): run() method completes or stop() is called. Thread cannot be restarted.

Diagram (Draw in Exam)

New ──start()──▶ Runnable ◀──────────────────────────┐
                    │                                  │
               scheduler                           notify()/
                    │                             sleep expires
                    ▼                                  │
                Running ──sleep()/wait()/join()──▶ Blocked
                    │
              run() completes
                    │
                    ▼
               Terminated

Key Methods

  • start() – starts thread, calls run()
  • sleep(ms) – makes thread sleep for ms milliseconds
  • wait() – releases lock, waits for notify()
  • join() – waits for another thread to finish
  • yield() – gives up CPU to same/higher priority thread
CH.4 Explain Servlet Life Cycle [5 M]

Definition

The Servlet Life Cycle defines the process from servlet creation to destruction, managed by the Servlet Container (like Tomcat).

Phases of Servlet Life Cycle

  1. Loading and Instantiation: Container loads servlet class and creates an instance when first request arrives.
  2. Initialization – init(): Called only ONCE after servlet is instantiated. Used to initialize resources like DB connections. Signature: public void init(ServletConfig config)
  3. Request Handling – service(): Called for EVERY client request. Determines request type (GET/POST) and calls doGet() or doPost(). Signature: public void service(HttpServletRequest req, HttpServletResponse res)
  4. Destroy – destroy(): Called only ONCE before servlet is removed from memory. Used to release resources. Signature: public void destroy()

Diagram (Draw in Exam)

Client Request
      │
      ▼
 [Servlet Container]
      │
      ├──▶ Load Class
      │
      ├──▶ new Servlet()
      │
      ├──▶ init()     ← ONCE
      │
      ├──▶ service()  ← EVERY REQUEST
      │       │
      │       ├──▶ doGet()
      │       └──▶ doPost()
      │
      └──▶ destroy()  ← ONCE (on shutdown)
CH.4 Explain JSP Life Cycle [4–5 M]

Definition

The JSP Life Cycle describes the series of steps a JSP page goes through from the moment it is first accessed to when it is destroyed.

Phases

  1. Translation: JSP file (.jsp) is converted to a Java Servlet source file (.java) by the JSP container.
  2. Compilation: The .java file is compiled into a .class (bytecode) file.
  3. Loading: The servlet class is loaded into JVM memory.
  4. Instantiation: A servlet object is created.
  5. Initialization – jspInit(): Called once. Used to initialize resources.
  6. Request Processing – _jspService(): Called for every client request. Contains JSP page logic.
  7. Destroy – jspDestroy(): Called once before JSP is removed. Releases resources.

Note for Exam

JSP Life Cycle is similar to Servlet Life Cycle PLUS the extra Translation and Compilation phases at the beginning. After compilation, JSP behaves exactly like a Servlet.

CH.3 Explain JDBC Architecture with Types of JDBC Drivers [5 M]

JDBC Architecture

JDBC API provides a standard interface between Java application and Database. It consists of two layers:

  • JDBC API Layer: Interface between Java application and JDBC driver manager. Uses java.sql package.
  • JDBC Driver Layer: Communicates with actual database. Each JDBC driver is specific to one database.

5 Steps to Connect to Database

  1. Load/Register Driver: Class.forName("com.mysql.Driver");
  2. Create Connection: Connection con = DriverManager.getConnection(url, user, pass);
  3. Create Statement: Statement st = con.createStatement();
  4. Execute Query: ResultSet rs = st.executeQuery("SELECT * FROM table");
  5. Close Connection: con.close();

Four Types of JDBC Drivers

  1. Type 1 – JDBC-ODBC Bridge Driver: Converts JDBC calls to ODBC calls. Platform-dependent. Slow. Only for testing. Requires ODBC driver installed.
  2. Type 2 – Native API Driver (Partially Java): Converts JDBC calls to database-specific native calls. Faster than Type 1. Platform-dependent. Requires native library.
  3. Type 3 – Network Protocol Driver (Middleware): Translates JDBC calls to middleware server protocol. Middleware server communicates with DB. Platform-independent. Good for internet.
  4. Type 4 – Thin Driver (Pure Java): Directly converts JDBC calls to database protocol. Pure Java. Platform-independent. Fastest. Most popular. Example: MySQL Connector/J.

Preferred

Type 4 is the most preferred for production as it is pure Java, portable, and has the best performance.

CH.4 Explain Scripting Elements in JSP [4–5 M]

Definition

Scripting elements allow embedding Java code in JSP pages. There are 4 types of scripting elements:

  1. JSP Declarations (<%! %>):
    Declares variables and methods at class level (outside service method).
    Syntax: <%! int count = 0; void display() { } %>
    Declared once, persists across requests.
  2. JSP Scriptlets (<% %>):
    Contains Java statements executed per request inside _jspService().
    Syntax: <% out.println("Hello"); for(int i=0;i<5;i++) { } %>
    Most commonly used for logic.
  3. JSP Expressions (<%= %>):
    Evaluates Java expression and prints result to output. No semicolon.
    Syntax: <%= new java.util.Date() %>
    Equivalent to out.println().
  4. JSP Comments (<%-- --%>):
    Comments not sent to client. Not visible in page source.
    Syntax: <%-- This is a JSP comment --%>
    Different from HTML comment <!-- which IS sent to client.
CH.5 Explain Spring Framework Architecture (Modules) [5 M]

Spring Architecture

Spring Framework is organized into modules grouped into containers. Key modules:

  1. Core Container: Foundation of Spring. Includes:
    • Core: Provides IoC and DI
    • Beans: Provides BeanFactory
    • Context: Builds on Core+Beans, loads components
    • SpEL: Spring Expression Language
  2. Web Container:
    • Web: Basic web integration
    • Web-Servlet: Spring MVC implementation
    • WebSocket: Two-way communication
    • Web-Portlet: MVC for portlet environment
  3. Data Access/Integration Layer:
    • JDBC: Abstracts JDBC coding
    • ORM: Integrates JPA, Hibernate, JDO
    • JMS: Java Messaging Service
    • Transactions: Programmatic and declarative
  4. AOP Module: Aspect-Oriented Programming. Method interceptors and pointcuts.
  5. Test Module: Supports testing with JUnit/TestNG.

Key Benefits of Architecture

Modular design allows developers to pick only needed modules. Loose coupling via DI. Clean separation of concerns.

P2 — Creating Thread (Two Ways) REPEATED 5×
// WAY 1: Extend Thread class
class MyThread extends Thread {
    public void run() {
        for(int i=1; i<=5; i++)
            System.out.println("Thread: " + i);
    }

// WAY 2: Implement Runnable interface

    public void run() {
        for(int i=1; i<=5; i++)
            System.out.println("Runnable: " + i);
    }

    }

P3 — JDBC: Insert and Display Records REPEATED 5×
import java.sql.*;
public class JDBCDemo {
    public static void main(String[] args) throws Exception {
        // Step 1: Load Driver
        Class.forName("com.mysql.jdbc.Driver");
        
        // Step 2: Get Connection
        Connection con = DriverManager.getConnection(
            "jdbc:mysql://localhost:3306/mydb", "root", "");
        
        // Step 3: Create Statement
        Statement st = con.createStatement();
        
        // Step 4a: Insert
        st.executeUpdate(
            "INSERT INTO student VALUES(1,'Rahul',85)");
        
        // Step 4b: Display
        ResultSet rs = st.executeQuery(
            "SELECT * FROM student");
        while(rs.next()) {
            System.out.println(rs.getInt(1) + " " +
                               rs.getString(2) + " " +
                               rs.getFloat(3));
        }
        
        // Step 5: Close
        con.close();
    }
}

P7 — Thread Synchronization Example Important
class SharedCounter {
    int count = 0;
    
    synchronized void increment() {  // synchronized method
        count++;
        System.out.println(Thread.currentThread().getName() 
                           + " Count: " + count);
    }
}

class MyThread extends Thread {
    SharedCounter sc;
    MyThread(SharedCounter sc) { this.sc = sc; }
    public void run() {
        for(int i=0; i<3; i++) sc.increment();
    }
}

public class SyncDemo {
    public static void main(String[] args) {
        SharedCounter sc = new SharedCounter();
        MyThread t1 = new MyThread(sc);
        MyThread t2 = new MyThread(sc);
        t1.start(); t2.start();
    }
}

  • Get: request.getCookies() → array
  • getName() and getValue() to read
doGet vs doPost — Key Diff
  • GET: URL visible, limited size, bookmarkable
  • POST: Hidden, no size limit, secure
  • GET: for reading; POST: for writing
Implicit Objects in JSP (9)
  • request, response, out, session
  • application, config, pageContext
  • page, exception
